# 旅痕 · 足迹图

点亮走过的每一座城，记录日期和备注，并按时间轴回放整条旅行足迹。目前支持中国和日本两张地图。

中国地图精确到**地级行政单元**（370 个：地级市 / 自治州 / 地区 / 盟，直辖市与港澳台各算一个，海南直管县单列），
边界数据来自高德开放的行政区划，经 Albers 等积投影和道格拉斯-普克简化后内置在 `public/data/cn.json`。

## 多国家

顶部是国家下拉框（默认中国），每个国家一张独立的地图、各用各的投影。

**地址栏带国家参数**：`/?country=JP`，分享出去打开就是日本。参数在**服务端**解析后传给客户端，
所以首屏直接取 `jp.json`，不会先加载中国地图再切过去。默认国家（中国）不写进地址，保持 `/` 干净。
参数非法或缺失都回落到中国。切换用 `router.replace` 而不是 `push`——来回切国家不该塞满后退历史。

| | 中国 | 日本 |
|---|---|---|
| 粒度 | 地级市 370 个 | 都道府県 47 个 |
| 投影 | Albers（基准 105°E，标准纬线 25°/47°） | Albers（基准 137°E，标准纬线 33°/45°） |
| 数据 | `public/data/cn.json` 520 KB | `public/data/jp.json` 42 KB |
| 小图 | 南海诸岛（含九段线） | 冲绳县 |

**为什么不共用一套投影**：Albers 是圆锥投影，离基准经线越远旋转越大。用中国那套（105°E）画日本，
福冈→东京的方位角会偏 -17.9°、东京→北海道偏 -21.3°，列岛看着整个是歪的。
各用各的基准经线后偏差降到 0.0°–2.2°。

数据模型上 `Visit.country` + `Visit.adcode` 联合定位（中国是 6 位行政区划码，日本是都道府県码 1–47）。
加第三个国家只要：跑一次 `scripts/build-map.py`、在 `src/lib/regions.ts` 加一项配置、
在 `validation.ts` 的 country 枚举里加一个值。

地图数据用 `scripts/build-map.py` 生成，投影参数、简化容差、要排除的远洋岛屿都记在里面。
日本的数据里包含南千岛群岛（俄罗斯管辖）和东京都的无人远洋岛，脚本里显式排除了。

## 本地跑起来

前置：Node 20+、Docker Desktop（需要**先启动**）。

```bash
cp .env.example .env        # 然后把 AUTH_SECRET 换成 openssl rand -base64 32 的输出
npm install
npm run db:up               # 起 Postgres，宿主机端口 5433
npm run db:push             # 建表
npm run db:seed             # 写入预置账号
npm run dev                 # http://localhost:3000
```

### 关于 db:push

建表走的是 `prisma db push` —— 把 `schema.prisma` 的当前状态直接推给数据库，
仓库里**没有 `prisma/migrations/`，也没有版本化的迁移历史**。改完 schema 再跑一次
`npm run db:push` 就同步了，不用生成迁移文件。

代价是：

- schema 怎么一步步演化过来的没有记录，别人拉下来只能得到当前快照
- 破坏性变更（删列、改字段类型）`db push` 会先提示，必要时要 `--accept-data-loss`。
  **动这类改动前先 `npm run db:backup`**
- 单人单机够用；将来要上多环境或生产，改用 `prisma migrate dev` 生成迁移文件

**不开放注册**，用预置账号登录：

| 邮箱 | 密码 |
|---|---|
| `me@traveller.local` | `traveller` |

改账号信息或再加一个人，重跑 seed 即可（已存在的账号只更新密码和昵称，不动足迹）：

```bash
SEED_EMAIL=you@example.com SEED_PASSWORD=你的密码 SEED_NAME=你的昵称 npm run db:seed
SEED_DEMO=1 npm run db:seed          # 顺便灌 11 条示例足迹（仅当该账号还没有足迹时）
```

> Docker Hub 在国内常拉不动。若 `npm run db:up` 卡在拉镜像，在
> Docker Desktop → Settings → Docker Engine 里加一行：
> `"registry-mirrors": ["https://docker.m.daocloud.io"]`

> 仓库里的 `.npmrc` 把源指向了 npmmirror —— 全局配置里的私有 nexus 需要鉴权，装公共包会 401。
> 如果你的 nexus 恢复了，删掉这个文件即可。

## 备份与恢复

```bash
npm run db:backup                          # 导出到 ./backups/
BACKUP_DIR=~/Documents/旅痕备份 npm run db:backup   # 换个地方存
```

导出的是 JSON，不是 `pg_dump`：可读、可 diff、跟数据库版本解耦，将来换 SQLite 或换机器也能导回去。
头像转成 base64 一并带走。自动轮转，保留最近 30 份。

恢复：

```bash
npm run db:restore backups/traveller-20260825-2118.json          # 演练，只报告不写入
npm run db:restore backups/traveller-20260825-2118.json --yes    # 真恢复
```

恢复会**先清空** User / Person / Visit 三张表再导入，所以默认先演练一遍。

### 定时执行

macOS 上加一条 cron（每天 22:00）：

```bash
crontab -e
# 加入这行（注意用绝对路径，cron 的环境很干净）
0 22 * * * /opt/homebrew/bin/node --env-file=.env scripts/backup.mjs >> backups/cron.log 2>&1
```

路径是这台机器上 `which node` 的实际结果；换机器要重新确认。
另外 Docker 没启动时备份会失败，日志记在 `backups/cron.log`。

### 两个要知道的

- **备份文件和数据库在同一块硬盘上，这防不了硬盘故障。** 真要防灾，把 `BACKUP_DIR`
  指到 iCloud / 坚果云 / Dropbox 这类会同步到云端的目录
- 备份里含账号的密码哈希（scrypt 派生值，不是明文）。文件本身没加密，别随手发给别人

### 恢复演练

备份没验证过等于没有。这套脚本做过完整往返验证：导出 → 在一次性测试库里恢复 →
逐字段比对（含头像二进制的 sha256），三张表完全一致。改动备份格式后建议重跑一次这个验证。

## 人物

足迹记在「人物」头上——一条到访属于谁。左栏「人物」标签页管理：

- 姓名必填，头像可选。每个人有一个**身份色**，从 8 色预设里挑（新建时按姓名哈希给个默认值）
- 身份色同时是文字头像底色、图例色、**地图上点亮城市的颜色**、回放涟漪的颜色。
  传了照片头像也不影响——颜色和照片是两个独立属性
- 头像在浏览器里裁成正方形、压到 256px 再上传，存进库的 `Person.avatarData`，
  经 `/api/persons/[id]/avatar` 取图（地址带 `?v=updatedAt`，换头像即换地址，可以长缓存）
- 删人物不会删他的到访记录，那些记录的 `personId` 置空，显示为「未指定」

新增到访时在表单顶部选人，**可多选**（同一趟出行涉及多个人）。只有一个人物时默认选中；
一个都没有时可以先不选，之后补。多个人时列表和详情里显示叠放的头像组，超过 3 个折成 +N。

数据结构是 `Visit` 和 `Person` 的多对多（Prisma 隐式关联表 `_VisitPerson`）。
早期版本是单外键 `Visit.personId`，迁移时先建关联表搬数据、逐条核对一致后才删旧列。

## 人物筛选

左栏统计卡下面是筛选条，点人物头像切换。语义是**「与」**：选中的人必须全都参与了那次到访。

- 选一个人 → 他**参与过**的全部到访（含同行）
- 选两个人 → 他俩**一起**去的
- 未指定的记录单独有个筛选项
- 「仅这些人」开关 → 严格匹配，要求参与者恰好就是选中的这些，排除有别人同行的。
  选一个人 + 开这个 = 他**单独**去的

只选一个人时提示条会拆开写「其中单独去 N 条 · 与人同行 M 条」——
不拆的话，两个人的筛选数相加会超过总数（同行记录被两边各算一次），看起来像算错了。

筛选同时作用于**地图、统计数字、足迹列表和回放**。地图配色也只取选中那几个人的颜色——
「只看某人」得到的是一张他的单色地图，不会因为同行记录里还有别人而继续显示多色。

城市详情面板**不受筛选影响**，永远显示这座城的全部到访（面板讲的是这座城的事实），
当前筛选下有记录被隐藏时会在面板里提示一句。

## 交互约定

- **单击**城市 → 右侧抽屉滑出，看详情
- **双击**灰色城市 → 直接进记录表单
- 一座城市可以记录**多次到访**，详情里按日期倒序列出，可单独编辑或删除；
  已点亮的城市详情底部是「再记一次到访」和「取消点亮」
- 删除都要二次确认，且是面板内联确认，不弹系统对话框
- 日期选择器点标题可逐级上钻：日 → 月 → 年，跨几十年只要几下
- 地图上的点亮状态取该城市**最早**一次到访
- **城市颜色 = 这座城所有到访涉及的人的身份色并集**。单人是纯色；多人沿对角线硬切成等宽色带
  （SVG 硬断点线性渐变，不混色）。所以一座城被不同人在不同时间去过，也会显示成多色。
  没指定人物的到访用中性灰
- 注意：SVG 里样式表会压过 `fill` 呈现属性，所以城市填充走 inline `style`，不能用 `fill=`
- 回放按**每一次到访**推进：同一座城去过两次就亮两次，重复到访是双圈涟漪，
  字幕上标「第 N 次」
- 回放节奏是**每条记录固定 1 秒**（不是整条时间轴匀速走完）——日期挨得再近的两条记录，
  注视时间也一样长。播放头在这 1 秒里从当前事件滑向下一个，滑到即点亮。
  右下角 `1×` 可切 0.5× / 1× / 2×（即每条 2 秒 / 1 秒 / 0.5 秒）

## 移动端

760px 以下切成竖屏布局：地图在上（54%）、列表在下（46%），两块各自滚动，页面本身不滚。

- 面板收起时，**筛选条会浮到地图底部**（圆角胶囊条，抓手上方）——收起就是为了看地图，
  而这时最想调的恰恰是筛选，藏在收起的面板里就够不到了。同时隐藏图例，因为筛选条本身就是色卡
- 底部列表**可以收起**：抓手往下滑或点一下收起，地图占满全屏，
  收起后抓手上显示「N 座城 · M 次到访」的摘要；往上滑或点一下展开。
  切换标签页会自动展开（点标签说明是要看内容）
- 抽屉从**底部升起**（不是右侧），顶部有抓手，最高 86dvh
- 地图手势：单指拖拽平移，**双指捏合缩放**（`ChinaMap` 自己处理多指 pointer 事件，
  因为 `#map` 设了 `touch-action: none`，浏览器原生缩放不会生效）
- 隐藏了标题栏、缩放按钮（有捏合就够了）、南海诸岛小图（三沙可以用搜索找到）
- 触摸设备上不显示悬浮提示，图例文案换成「点城市看详情」——双击在手机上不是自然手势，
  灰色城市点开后用「记录一次旅行」按钮
- 日历格子、删除按钮、人物胶囊、筛选胶囊的点按区域都放大了；色板从 22px 放到 30px
- 竖屏地图/列表是 50/50 分——统计卡 + 筛选条 + 标签页占掉不少，列表得留够高度

**横屏手机**（≤940px 且 ≤500px 高）单独一套：竖着堆会把地图压扁，改回左右分栏、抽屉回到右侧。

**平板**（761–1099px）：抽屉拉开后地图剩不下多少，工具栏整条淡出，关掉抽屉自然回来——
硬挤会把搜索框压成一条缝。1100px 以上才做「工具栏左移让位」。

其它移动端细节：

- 表单控件在小屏强制 16px：iOS Safari 会在聚焦更小字号的输入框时自动放大整页且不缩回
- 底部浮层（抽屉、回放条、图例）都垫了 `env(safe-area-inset-*)`，避开 Home 指示条和刘海
- 回放时间轴的年份刻度按轨道实际宽度抽稀（`ResizeObserver` 量宽度，按 2/5/10/20 年递进），
  从最新一年往回抽，保证最右边一定有标签
- 点按不出灰色高亮块，按钮 `touch-action: manipulation` 去掉 300ms 延迟

760px 以上仍是三栏（左栏 + 地图 + 右侧抽屉），1180px 以下左栏收窄到 288px。
