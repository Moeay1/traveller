# 区县下钻设计文档

- 日期：2026-09-18
- 分支：`feat/county-drilldown/zhaoshichang`
- 交互原型：https://claude.ai/code/artifact/8ce8d936-b087-4941-8d54-ac7d941865a2
  （原型里的区县几何是按市界现场切的示意数据，交互和视觉状态是准的，边界不是）

## 1. 目标

中国地图在现有 370 个地级单元之下增加一层区县（县级行政区），支持以区县为粒度记录到访。

明确**不做**的部分：

- 日本保持单层（都道府県）。架构要支持「某个国家只有一层」，但不生成日本的市区町村数据。
- 不为区县做独立的回放时间轴，复用现有回放。
- 不处理港澳台与三沙的下级区划（数据源质量不一，见 §2.4）。

## 2. 数据管线

### 2.1 两层必须在同一个坐标空间里

这是整个方案的前提，也是最容易做错的地方。

区县层不是另一张图，是全国图的放大细节层。要做到市界与区县界严丝合缝对上、区县能直接叠在现有 SVG 上，区县多边形必须与 `cn.json` 的市多边形处于**完全相同的投影与归一化变换**下：

1. 同一套 Albers 参数：`lon0=105, lat0=35, p1=25, p2=47`
2. 同一组归一化常量：`minx, miny, scale, H`（`x' = (x-minx)*scale`，`y' = H-(y-miny)*scale`）

问题在于现有 `cn.json` 是更早生成的，`scripts/build-map.py` 里只留了参数注释，**没有保存 `minx/miny/scale/H`**。

**不要重新生成 `cn.json` 来解决这件事。** `src/lib/regions.ts` 里的 `view: { x: -14, y: -14, w: 1028, h: 874 }` 和 `inset.viewBox: '650 795 210 358'` 都是在这份文件的坐标空间里手调出来的常量，重新生成一旦有零点几的漂移，南海诸岛小图会悄悄错位，而且没有任何测试会报警。现有 `cn.json` 应当被当作不可变的基准。

正确做法是**标定**出它的变换，然后复用：

1. 变换只有三个自由度。`X = (x-minx)·s`、`Y = H-(y-miny)·s` 可以写成 `X = s·x + a`、`Y = -s·y + b`，待求的就是 `(s, a, b)`。
2. 取对应点：`dp()` 抽稀总是保留折线首点，所以 `cn.json` 里每个环的首顶点必然是源数据该环投影后的首顶点 —— 这是精确对应关系，不是近似匹配。
3. 粗估：**必须拿两侧完全相同的要素集合对齐包围盒。** 取 `530000_full.json`（云南的地级单元），与 `cn.json` 里 adcode 前两位是 53 的那批单元对齐 —— 两边是同一批市，包围盒可以直接对应。
   最初写的是「拿全国省级数据的包围盒对齐 `cn.json` 全部单元的包围盒」，**这是错的**：`cn.json` 含三沙市（`h` 到 1147），而省级数据的最南端是另一回事，`b` 会偏出几百个单位，最近邻一组对应点都配不上（实测粗估 `b₀=444` vs 正确值 `454`，`tol=8` 下零配对）。
4. 精算：投影每个环的首顶点，在粗估变换下与 `cn.json` 中同 adcode 单元的环首顶点做最近邻配对（按距离，不按下标 —— 环的顺序会因为丢环而错位），最小二乘拟合 `(s, a, b)`，迭代两轮。
   令 `u = x-x̄`、`U = X-X̄`、`v = y-ȳ`、`V = Y-Ȳ`，则
   `s = (ΣuU - ΣvV) / (Σu² + Σv²)`，`a = X̄ - s·x̄`，`b = Ȳ + s·ȳ`。
   `ΣvV` 前面是**减号**：y 方向带翻转，残差是 `-s·v - V`，求导后符号与 x 方向相反。写成加号会得到 `s·(Σu²-Σv²)/(Σu²+Σv²)`，在南北跨度大的数据上偏得很明显，而且看起来仍然"差不多对"。`test_mapkit.py` 里有一个用精确合成数据做的回归专门钉这个符号。
5. **验收**：最大残差须 < 0.06（`cn.json` 坐标保留 1 位小数，理论上界 ±0.05）。超出就说明投影参数推断错了，停下来查，不要继续往下做。
6. **留出验证集**：用 `510000_full.json`（四川）做 holdout，同样算残差。拟合集和验证集残差量级不一致，说明拟合过了或数据源版本不一致。

标定结果落到 `scripts/cn-transform.json`，由生成区县的脚本读取。它是构建期产物，前端不读，也不进 `cn.json`。

### 2.2 区县分片

- 数据源：`https://geo.datav.aliyun.com/areas_v3/bound/{adcode}_full.json`，对 `cn.json` 里每个地级单元的 adcode 各取一次，返回该单元下级区划的 FeatureCollection
- 简化容差：区县比地级市小一个量级，`eps` 要更小。取 `0.00012`（实测体积达标，最终没有调整）
- 坐标精度：保留 2 位小数（市级是 1 位）。区县在 1000 宽坐标系里只有几个单位宽，1 位小数会出现可见的锯齿
- 输出：**每市一片**，`public/data/cn/{adcode}.json`

```jsonc
{
  "p": 530100,                                   // 父级市 adcode
  "u": [                                         // 字段名与 MapUnit 对齐，少一层映射
    { "n": "五华区", "a": 530102, "c": [498.3, 678.1], "g": [[...]] }
  ]
}
```

没有 `w/h`：坐标已经在全国空间里，不需要各自的包围盒。

- 索引：`public/data/cn/index.json`

```jsonc
{
  "src": "geo.datav.aliyun.com/areas_v3",
  "fetchedOn": "2026-09-18",                     // 区划调整比地级市频繁，记下抓取日期
  "eps": 0.00012,
  "skipped": [419001, 429004],                   // 没有下级区划的单元，前端据此不去请求
  "shards": { "530100": { "n": 14, "size": 12838 } }
}
```

`src`/`fetchedOn` 是给下次重抓时对照用的；`shards` 给前端做预取决策，也是体积回归的基线。

- 名录：`public/data/cn/names.json`，只有 `[{ a, n, p }]`（区县码、区县名、父级市码），无几何。实测 2812 条 / 112.2KB。搜索要用，见 §8。

### 2.3 体积实测

`COUNTY_EPS = 0.00012` 下的实际结果（2026-09-18 抓取）：

| 指标 | 目标 | 实测 |
|---|---|---|
| 分片数 | — | **332**（370 个地级单元减去 38 个没有下级的） |
| 合计体积 | ≤ 12MB | **2.62MB** |
| 单片中位 | — | **7.2KB** |
| 单片最大 | ≤ 40KB | **39.3KB** |
| 区县总数 | — | **2812** |
| `names.json` | — | **112.2KB**（无几何） |
| 对齐最大偏差 | ≤ 0.6 | **0.15**（零告警） |

面积悬殊的五个试点：深圳 3.6KB/9 区县 · 上海 7.1KB/16 · 昆明 12.5KB/14 · 呼伦贝尔 28.2KB/14 · 那曲 34.1KB/11。

两个结论直接影响 §9 的加载设计：

- **下钻不需要显式 loading 态。** 中位 7.2KB 的分片在本地缓存 + 相邻预取之后基本无感，右上角那条细进度条只在冷启动连取十几片时才有意义。这正好落回「不要用遮罩打断连续动作」。
- **`names.json` 比预估的 60KB 大了近一倍**（112KB / 2812 条）。仍然可以在 `requestIdleCallback` 里拉，但不要塞进首屏包。

#### 不要用面积比判断对齐

本来打算用「每个市的区县面积之和 vs 该市面积，误差 < 1%」做对齐回归。**这个判据是错的**，首轮实测 323 片里有 21 个过不了，但它们的几何其实是对的：

区县层容差 `0.00012` 比市层的 `0.00035` 细得多，会保留市界抽稀时丢掉的小岛。舟山市界 20 个环，区县 71 个环，面积因此多出 **25%**；珠海 5 → 25 个环，多 5.6%。反过来乌海这种小市只有 1 个环，纯抽稀差异就有 3.4%。面积比量的是**两层细节多少**，不是**有没有对齐**。

正确判据是**包围盒单向包含**：区县包围盒可以向外扩（那是多出来的岛，正常），但市界不该探出区县包围盒之外 —— 那才说明套错了变换。容忍量 `ALIGN_LIMIT = 0.6`（实测内陆大市 0.05，天津 0.10，乌海 0.19）。

面积比仍然打印，当「细节比」看，不作为闸门。

真正证明两层同空间的是 `scripts/verify_transform.py`：整环逐顶点比对，云南/四川/内蒙古最大偏差 0.0590，与 1 位小数的量化噪声同量级。

### 2.4 跳过的单元

实测跳过 38 个（370 = 332 + 38），分两类：

- **显式 SKIP（4 个）**：`460300` 三沙市、`710000` 台湾、`810000` 香港、`820000` 澳门 —— 下级区划数据缺失或质量不一。
- **数据源确实没有下级（34 个）**：`{adcode}_full.json` 返回 404。都是本身就是县级、或不设区的地级市 —— 海南直管县（`469xxx`、`460400` 儋州）、新疆自治区直辖县级市（`659xxx`）、省直辖县级行政区（`419001` 济源、`429004` 仙桃等）、不设区的地级市（`441900` 东莞、`442000` 中山、`620200` 嘉峪关）。

这批单元在地图上停留在市层就是正确的 —— 它们没有下一级。前端遇到 `index.json` 的 `skipped` 里的市，下钻时该市保持市级样态，不发请求、不报错。

**每次重抓都要核对这份清单。**数据源不稳（见 §13），正常地级市如果出现在跳过清单里，就是网络把它吞了 —— 首轮全量跑就有 9 个（大连、南阳、茂名等）因为连续截断耗尽重试被误跳过。

## 3. 数据模型

```prisma
model Visit {
  // ...
  /// 记录粒度：'city' 市级（含本次改动之前的全部老记录）· 'county' 区县级
  level String @default("city")
  /// 区县级记录的父级市 adcode；市级记录为 null。
  /// 冗余存一份，全国层做聚合时不用再查地图数据
  parentAdcode Int?
  // ...
  @@index([userId, country, parentAdcode])
}
```

- `adcode` 的语义变成「这条记录所在地图单元的代码」，是市码还是区县码由 `level` 决定。中国的市码和区县码都是 6 位，不靠 `level` 区分不开。
- 迁移：`level` 有默认值 `'city'`，老记录自动就是正确的；`parentAdcode` 留 null。不需要数据回填。
- 应用层校验（不做 DB 约束）：
  - 跨字段规则在 `src/lib/validation.ts` 的 `visitInputSchema.superRefine` 里：`level='county'` 要求 `parentAdcode` 必填、且不等于 `adcode`、且 `country='CN'`；`level='city'` 要求 `parentAdcode` 为 null。
  - 「`parentAdcode` 是否真的是这个区县的父级市」要查名录，放在 API 路由里（zod 里做不了异步读文件）。
- 按项目既有做法走 `prisma db push`（README 里已说明这个取舍）。**迁移已验证**：43 条老记录全部自动落到 `level='city'` / `parentAdcode=null`，不需要回填。

#### 父级市不能靠 adcode 前缀推

中国区划码是「省2+市2+县2」，看着 `floor(adcode/100)*100` 就是父级市。**对 86 个区县是错的** —— 四个直辖市在 `cn.json` 里是整体单元（北京 `110000`），而东城区是 `110101`，前缀推出 `110100`，那是地图上不存在的码，那座城永远不会被点亮。

所以服务端必须查 `public/data/cn/names.json`（P1 生成的无几何名录，2812 条 / 112KB）。`src/lib/counties.ts` 进程内只解析一次，提供 `parentOfCounty()` / `resolveCountyName()`。

#### 取消点亮要连区县记录一起删

`DELETE /api/visits?adcode=X` 原本是「删掉该 adcode 的全部到访」。加了区县之后这会留下一个很别扭的 bug：区县记录的 `adcode` 是区县码，按市码删删不到，而按 §6 的点亮规则那座城仍然是亮的 —— 用户点了「取消点亮」，城还亮着。

改成 `OR: [{ adcode }, { parentAdcode: adcode }]`。这一个写法同时覆盖两种语义：传市码连区县一起删，传区县码只删那个区县（区县没有下级，`parentAdcode` 分支命中不了任何记录）。已用真实数据库验证：旧写法 3 条只命中 1 条，新写法全扫、零残留。

## 4. 层级抽象

`src/lib/regions.ts` 的 `Region` 从「单层 + 一组标签」改成层级数组：

```ts
type MapLevel = {
  key: 'city' | 'county'
  source:
    | { kind: 'bundle'; url: string }                        // 整包，启动时取
    | { kind: 'shard'; dir: string; index: string; names: string }  // 按父级分片，按需取
  /** 统计口径的称呼：'座城' / '个区县' */
  unitLabel: string
  /** 进入该层的视窗宽阈值 [淡入开始, 完全接管]；最外层没有 */
  band?: [number, number]
}
```

- 中国：`[{ city, bundle }, { county, shard, band: [210, 110] }]`
- 日本：`[{ city, bundle }]` —— 只有一层，所有下钻相关的 UI 自动不出现
- `DEFAULT_REGION`、`regionOf()` 的签名不变

`band` 的两个数是视窗宽（用户单位）。210 约等于一两个省的跨度，110 以下区县完全接管。这两个数在原型里调过，是可用的起点。

## 5. 地图组件

`ChinaMap.tsx` 现在 399 行，塞进区县层会到 600+，且会同时管两层的渲染、两套标签、手势、面包屑。按职责拆开：

```
src/components/map/
├─ MapCanvas.tsx      SVG 容器、视窗状态、手势（wheel/drag/pinch）、MapHandle
├─ CityLayer.tsx      市的填充/描边/标签/小图（南海诸岛、冲绳）
├─ CountyLayer.tsx    区县的填充/描边/标签，只渲染可见市
└─ Breadcrumb.tsx     中国 › 省 › 市
src/lib/mapview.ts    视窗数学：纯函数，可单测
```

`src/lib/mapview.ts` 收口下面这些，全部是纯函数：

- `progress(viewW, band)` → 0..1 的下钻进度
- `fitBox(bbox, k, minW?)` → 把包围盒装进视窗
- `drillBox(bbox, band)` → 下钻目标视窗，保证落进 band 内（见 §5.1 第 5 条）
- `visibleUnits(units, view, pad)` → 视窗内的单元
- `labelScale(viewW, containerPx)` → 标签/斜纹的缩放补偿系数

### 5.1 原型里踩出来的五条必须遵守项

这几条都是在原型里真实撞到过的，不是理论担心：

1. **市界必须渲染在区县层之上**，单独一层，只描边、`fill:none`、`pointer-events:none`。放在下面会被区县的填色直接糊掉，下钻后完全看不出市的边界在哪。这一层同时承担「市界在下钻时加粗、升级成分组线」的视觉职责。
2. **填充层一律 `pointer-events:none`，命中层显式 `pointer-events:all`。** 点亮的市在描边层上是 `fill:none`（让下面的彩色填充透出来），SVG 里 `fill:none` 就只有描边能命中，点市会从缝里漏到下面没有 `data-adcode` 的填充层上 —— 结果是**点亮的城市点不中**。这个问题在现有代码里就可能已经存在，实现时先去 `ChinaMap.tsx` 查一遍。
3. **标签字号、标签白描边宽度、斜纹 pattern 尺寸都在用户坐标里**，不做补偿的话放大后字会涨成巨人、斜纹粗成色块。统一乘 `labelScale = 视窗宽 / 容器像素宽`，然后按屏幕 px 写尺寸。现有 `.lbl` 有同样的隐患，只是主视窗基本不动所以没暴露出来。
4. **视窗变化后要重算 tooltip。** 视窗动了而鼠标没动，光标底下换了一个单元，提示却还留着上一个。记住最后一次光标位置，视窗每次更新用 `elementFromPoint` 重新解析一次。现有的滚轮缩放有同样的问题。
5. **下钻目标视窗宽必须 ≤ band 下界。** 呼伦贝尔这种大市，整市装进视窗时视窗宽还在 band 之外，区县永远出不来，「进入区县层」会变成死按钮。装不下就只看一部分，可以拖。

## 6. 点亮与聚合语义

混合粒度是这次改动真正的设计难点：库里既有老的市级记录，也会有新的区县级记录。

- **市点亮** = 有 `level='city'` 的记录 **或** 有任一 `level='county'` 且 `parentAdcode` 等于该市的记录
- **区县三态**：

| 状态 | 条件 | 表现 |
|---|---|---|
| `lit` | 该区县有 county 记录 | 人物身份色填充（多人对角分色，沿用现有逻辑） |
| `inherit` | 该区县无记录，但所属市有 city 记录 | 斜纹（`--lit` 在 `--lit-soft` 上，45°，6px 一道） |
| `blank` | 都没有 | 底色 `--land` |

`inherit` 是这套设计里唯一的新视觉状态，它一次解决两件事：老记录不用回填也有合理的呈现；它自己就是「下一步该记什么」的提示。点开一个斜纹区县，抽屉要说清楚它为什么是斜纹，并允许就地补一条区县记录。

- **颜色**：沿用现有 `cityColors` 的人物色聚合与筛选语义，只是聚合的 key 跟着当前层级换（市码 / 区县码）
- **统计**：侧栏在「N 座城」之后加「M 个区县」，再加一条待细化提示「X 座城只记到了市」

## 7. 回放

- 全国层 / 市层：区县级记录折叠到 `parentAdcode` 点亮，涟漪画在**市**的锚点上
- 区县层：涟漪画在**区县**的锚点上

在 `src/lib/visit.ts` 里加 `foldToLevel(visits, level)`，回放和 `lit` 计算都走它，不要在组件里各写一遍。

## 8. 搜索

`CitySearch` 改成跨层搜索。两个要求：

- 区县结果必须带父级市消歧 —— 全国重名的「城关区」「新华区」一大把，只显示区县名等于没法选
- 未加载分片里的区县也要能搜到 —— 所以需要 §2.2 的 `names.json`，页面启动后在空闲时（`requestIdleCallback`）拉取

选中一个区县的搜索结果 = 下钻到它所属的市 + 选中该区县。

## 9. 加载与缓存

- 分片按需取，内存里 `Map<adcode, CountyShard>` 缓存，切国家不清空
- 触发时机：视窗进入 band 时，对可见市（bbox 相交，`pad = 视窗宽 * 0.15`，最多 40 个）并发取，并发上限 6
- 加载中：该市的区县层不渲染，市保持市级样态。band 内有未加载分片时，地图右上角显示一条细进度条 —— 不要全屏 loading，下钻是个连续动作，遮罩会把它打断
- 预取：下钻到某市后，空闲时预取相邻的市（按锚点距离取最近 8 个）
- 取失败：该市保持市级样态，右上角给一次可重试的轻提示，不弹窗

## 10. 性能

- **区县层不要用 `feDropShadow`。** 现在点亮的市靠 `filter="url(#soft)"` 托底投影，区县数量上来之后滤镜数量是渲染开销的第一嫌疑。区县层改用描边表达层次。
- 区县 path 按「可见市集合 + 选中态」做 key 缓存，集合没变就不重建 DOM（原型里验证过，这一条是区县层能流畅拖动的关键）
- 目标：区县层拖拽稳定 60fps；首次下钻到可交互 < 400ms，分片已缓存时 < 50ms

### P4 的一条经验

区县选中相关的三个 bug（搜索/侧栏点市时抽屉停在区县、足迹列表打不开区县记录、进度显示 `1/0`）**全部逃过了 `tsc` 和单测**，只有真的去点 UI 才暴露。根因是 `selected`（市）和 `countySel`（区县）两个并行的选中状态 —— 任何一个入口忘了清另一个就出错。

现在三个入口（地图点击、搜索、足迹列表）统一走 `selectCity()` / `selectCounty()`。P5 如果还要动选中逻辑，优先考虑合并成单一的 `sel` 判别联合，而不是继续加第三个状态。

P1 是闸门：体积或几何对齐不达标，后面全部要重新评估。

## 13. 风险

- ~~**标定拟合不出来。**~~ **已关闭**（2026-09-18）。拟合集（云南 16 点）最大残差 0.0562，验证集（四川 25 点）0.0557，两者同量级且都压在 1 位小数的量化下界 ±0.05 上 —— 残差里没有系统性成分，`lon0=105, lat0=35, p1=25, p2=47` 就是当初生成 `cn.json` 的那一组。`scripts/verify_transform.py` 用整环逐顶点独立复核（云南/四川/内蒙古），最大偏差 0.0590。
- ~~**分片体积未实测。**~~ **已关闭**（2026-09-18）。见 §2.3 实测表，合计 2.62MB / 单片最大 39.3KB，`eps` 不用动。
- **数据源不稳。** `geo.datav.aliyun.com` 在实测中大约每三次请求就有一次传到一半断掉。`fetch_json` 已经做了原子缓存 + 6 次重试，但第一轮全量跑仍有 9 个地级市（大连、南阳、茂名等）耗尽重试被误跳过。**重跑后一定要核对跳过清单**：只应出现县级单元和不设区的地级市，出现正常地级市就是网络吞了。
- **区划调整。** 撤县设区比地级市变动频繁，adcode 会变。`index.json` 里记 `fetchedOn` 和数据源版本，重抓时能对照出哪些市的下级变了。
- **band 阈值的手感。** 210/110 是在 1180px 宽的原型里调的，不同容器宽度下手感会变。P5 要在真机上复核，必要时把 band 改成按容器宽度归一化。
