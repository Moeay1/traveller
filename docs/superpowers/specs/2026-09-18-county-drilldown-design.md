# 区县下钻设计文档

- 日期：2026-09-18
- 分支：`feat/county-drilldown/zhaoshichang`
- 交互原型：https://claude.ai/code/artifact/8ce8d936-b087-4941-8d54-ac7d941865a2
  （原型里的区县几何是按市界现场切的示意数据，交互和视觉状态是准的，边界不是）

## 1. 目标

中国地图在现有 370 个地级单元之下增加一层区县（县级行政区），支持以区县为粒度记录到访。

明确**不做**的部分：

- 日本保持单层（都道府県）。架构要支持「某个国家只有一层」，但不生成日本的市区町村数据。
- 不为区县做独立的回放时间轴，复用现有回放。
- 不处理港澳台与三沙的下级区划（数据源质量不一，见 §2.4）。

## 2. 数据管线

### 2.1 两层必须在同一个坐标空间里

这是整个方案的前提，也是最容易做错的地方。

区县层不是另一张图，是全国图的放大细节层。要做到市界与区县界严丝合缝对上、区县能直接叠在现有 SVG 上，区县多边形必须与 `cn.json` 的市多边形处于**完全相同的投影与归一化变换**下：

1. 同一套 Albers 参数：`lon0=105, lat0=35, p1=25, p2=47`
2. 同一组归一化常量：`minx, miny, scale, H`（`x' = (x-minx)*scale`，`y' = H-(y-miny)*scale`）

问题在于现有 `cn.json` 是更早生成的，`scripts/build-map.py` 里只留了参数注释，**没有保存 `minx/miny/scale/H`**。所以第一步必须是：

- 把 `cn` 补成 `build-map.py` 里的正式配置项（数据源 `geo.datav.aliyun.com`，`eps=0.00035`）
- 重新生成 `cn.json`，并把变换常量写进文件：`{ w, h, u, jd, pv, tf: { minx, miny, scale, h } }`
- **视觉回归**：新旧 `cn.json` 逐单元比对锚点与包围盒，最大坐标差须 < 0.5（1000 宽坐标系里约 0.05%）。超出就说明投影参数推断错了，停下来查，不要继续往下做。

`tf` 字段是新增的，前端不读它，只有 `build-map.py` 生成区县时读。

### 2.2 区县分片

- 数据源：`https://geo.datav.aliyun.com/areas_v3/bound/{adcode}_full.json`，对 `cn.json` 里每个地级单元的 adcode 各取一次，返回该单元下级区划的 FeatureCollection
- 简化容差：区县比地级市小一个量级，`eps` 要更小。起点取 `0.00012`，按 §2.3 的体积目标调
- 坐标精度：保留 2 位小数（市级是 1 位）。区县在 1000 宽坐标系里只有几个单位宽，1 位小数会出现可见的锯齿
- 输出：**每市一片**，`public/data/cn/{adcode}.json`

```jsonc
{
  "p": 530100,                                   // 父级市 adcode
  "u": [                                         // 字段名与 MapUnit 对齐，少一层映射
    { "n": "五华区", "a": 530102, "c": [498.3, 678.1], "g": [[...]] }
  ]
}
```

没有 `w/h`：坐标已经在全国空间里，不需要各自的包围盒。

- 索引：`public/data/cn/index.json`

```jsonc
{
  "src": "geo.datav.aliyun.com/areas_v3",
  "fetchedOn": "2026-09-18",                     // 区划调整比地级市频繁，记下抓取日期
  "eps": 0.00012,
  "shards": { "530100": { "n": 14, "size": 23117 } }
}
```

`src`/`fetchedOn` 是给下次重抓时对照用的；`shards` 给前端做预取决策，也是体积回归的基线。

- 名录：`public/data/cn/names.json`，只有 `[{ a, n, p }]`（区县码、区县名、父级市码），无几何。全量约 2800 条，预计 60KB 左右。搜索要用，见 §8。

### 2.3 体积目标与验收

这是唯一一个还没有实测数字的地方，**P1 的第一个任务就是把它测出来**：

- 单市分片 ≤ 40KB（决定下钻要不要显式 loading 态）
- 全国合计 ≤ 12MB（只影响仓库与部署，不影响首屏）
- 几何对齐回归：每个市的区县面积之和 vs 该市面积，误差 < 1%

先拿面积悬殊的几个市试：昆明(530100)、上海(310000)、深圳(440300)、呼伦贝尔(150700)、那曲(540600)。如果单片中位数明显超 40KB，回头调 `eps`，不要靠前端硬扛。

### 2.4 跳过的单元

`460300` 三沙市、`810000` 香港、`820000` 澳门、`710000` 台湾 —— 下级区划数据缺失或质量不一，脚本跳过，并在运行结束时把跳过清单打印出来。前端遇到没有分片的市，下钻时该市保持市级样态（不是报错）。

## 3. 数据模型

```prisma
model Visit {
  // ...
  /// 记录粒度：'city' 市级（含本次改动之前的全部老记录）· 'county' 区县级
  level String @default("city")
  /// 区县级记录的父级市 adcode；市级记录为 null。
  /// 冗余存一份，全国层做聚合时不用再查地图数据
  parentAdcode Int?
  // ...
  @@index([userId, country, parentAdcode])
}
```

- `adcode` 的语义变成「这条记录所在地图单元的代码」，是市码还是区县码由 `level` 决定。中国的市码和区县码都是 6 位，不靠 `level` 区分不开。
- 迁移：`level` 有默认值 `'city'`，老记录自动就是正确的；`parentAdcode` 留 null。不需要数据回填。
- 应用层校验（`src/lib/validation.ts`，不做 DB 约束）：
  - `level='county'` 时 `parentAdcode` 必填
  - `parentAdcode` 必须确实是 `adcode` 所属的市（查已加载的分片索引校验）
  - `level='city'` 时 `parentAdcode` 必须为 null
- 按项目既有做法走 `prisma db push`（README 里已说明这个取舍）。

## 4. 层级抽象

`src/lib/regions.ts` 的 `Region` 从「单层 + 一组标签」改成层级数组：

```ts
type MapLevel = {
  key: 'city' | 'county'
  source:
    | { kind: 'bundle'; url: string }                        // 整包，启动时取
    | { kind: 'shard'; dir: string; index: string; names: string }  // 按父级分片，按需取
  /** 统计口径的称呼：'座城' / '个区县' */
  unitLabel: string
  /** 进入该层的视窗宽阈值 [淡入开始, 完全接管]；最外层没有 */
  band?: [number, number]
}
```

- 中国：`[{ city, bundle }, { county, shard, band: [210, 110] }]`
- 日本：`[{ city, bundle }]` —— 只有一层，所有下钻相关的 UI 自动不出现
- `DEFAULT_REGION`、`regionOf()` 的签名不变

`band` 的两个数是视窗宽（用户单位）。210 约等于一两个省的跨度，110 以下区县完全接管。这两个数在原型里调过，是可用的起点。

## 5. 地图组件

`ChinaMap.tsx` 现在 399 行，塞进区县层会到 600+，且会同时管两层的渲染、两套标签、手势、面包屑。按职责拆开：

```
src/components/map/
├─ MapCanvas.tsx      SVG 容器、视窗状态、手势（wheel/drag/pinch）、MapHandle
├─ CityLayer.tsx      市的填充/描边/标签/小图（南海诸岛、冲绳）
├─ CountyLayer.tsx    区县的填充/描边/标签，只渲染可见市
└─ Breadcrumb.tsx     中国 › 省 › 市
src/lib/mapview.ts    视窗数学：纯函数，可单测
```

`src/lib/mapview.ts` 收口下面这些，全部是纯函数：

- `progress(viewW, band)` → 0..1 的下钻进度
- `fitBox(bbox, k, minW?)` → 把包围盒装进视窗
- `drillBox(bbox, band)` → 下钻目标视窗，保证落进 band 内（见 §5.1 第 5 条）
- `visibleUnits(units, view, pad)` → 视窗内的单元
- `labelScale(viewW, containerPx)` → 标签/斜纹的缩放补偿系数

### 5.1 原型里踩出来的五条必须遵守项

这几条都是在原型里真实撞到过的，不是理论担心：

1. **市界必须渲染在区县层之上**，单独一层，只描边、`fill:none`、`pointer-events:none`。放在下面会被区县的填色直接糊掉，下钻后完全看不出市的边界在哪。这一层同时承担「市界在下钻时加粗、升级成分组线」的视觉职责。
2. **填充层一律 `pointer-events:none`，命中层显式 `pointer-events:all`。** 点亮的市在描边层上是 `fill:none`（让下面的彩色填充透出来），SVG 里 `fill:none` 就只有描边能命中，点市会从缝里漏到下面没有 `data-adcode` 的填充层上 —— 结果是**点亮的城市点不中**。这个问题在现有代码里就可能已经存在，实现时先去 `ChinaMap.tsx` 查一遍。
3. **标签字号、标签白描边宽度、斜纹 pattern 尺寸都在用户坐标里**，不做补偿的话放大后字会涨成巨人、斜纹粗成色块。统一乘 `labelScale = 视窗宽 / 容器像素宽`，然后按屏幕 px 写尺寸。现有 `.lbl` 有同样的隐患，只是主视窗基本不动所以没暴露出来。
4. **视窗变化后要重算 tooltip。** 视窗动了而鼠标没动，光标底下换了一个单元，提示却还留着上一个。记住最后一次光标位置，视窗每次更新用 `elementFromPoint` 重新解析一次。现有的滚轮缩放有同样的问题。
5. **下钻目标视窗宽必须 ≤ band 下界。** 呼伦贝尔这种大市，整市装进视窗时视窗宽还在 band 之外，区县永远出不来，「进入区县层」会变成死按钮。装不下就只看一部分，可以拖。

## 6. 点亮与聚合语义

混合粒度是这次改动真正的设计难点：库里既有老的市级记录，也会有新的区县级记录。

- **市点亮** = 有 `level='city'` 的记录 **或** 有任一 `level='county'` 且 `parentAdcode` 等于该市的记录
- **区县三态**：

| 状态 | 条件 | 表现 |
|---|---|---|
| `lit` | 该区县有 county 记录 | 人物身份色填充（多人对角分色，沿用现有逻辑） |
| `inherit` | 该区县无记录，但所属市有 city 记录 | 斜纹（`--lit` 在 `--lit-soft` 上，45°，6px 一道） |
| `blank` | 都没有 | 底色 `--land` |

`inherit` 是这套设计里唯一的新视觉状态，它一次解决两件事：老记录不用回填也有合理的呈现；它自己就是「下一步该记什么」的提示。点开一个斜纹区县，抽屉要说清楚它为什么是斜纹，并允许就地补一条区县记录。

- **颜色**：沿用现有 `cityColors` 的人物色聚合与筛选语义，只是聚合的 key 跟着当前层级换（市码 / 区县码）
- **统计**：侧栏在「N 座城」之后加「M 个区县」，再加一条待细化提示「X 座城只记到了市」

## 7. 回放

- 全国层 / 市层：区县级记录折叠到 `parentAdcode` 点亮，涟漪画在**市**的锚点上
- 区县层：涟漪画在**区县**的锚点上

在 `src/lib/visit.ts` 里加 `foldToLevel(visits, level)`，回放和 `lit` 计算都走它，不要在组件里各写一遍。

## 8. 搜索

`CitySearch` 改成跨层搜索。两个要求：

- 区县结果必须带父级市消歧 —— 全国重名的「城关区」「新华区」一大把，只显示区县名等于没法选
- 未加载分片里的区县也要能搜到 —— 所以需要 §2.2 的 `names.json`，页面启动后在空闲时（`requestIdleCallback`）拉取

选中一个区县的搜索结果 = 下钻到它所属的市 + 选中该区县。

## 9. 加载与缓存

- 分片按需取，内存里 `Map<adcode, CountyShard>` 缓存，切国家不清空
- 触发时机：视窗进入 band 时，对可见市（bbox 相交，`pad = 视窗宽 * 0.15`，最多 40 个）并发取，并发上限 6
- 加载中：该市的区县层不渲染，市保持市级样态。band 内有未加载分片时，地图右上角显示一条细进度条 —— 不要全屏 loading，下钻是个连续动作，遮罩会把它打断
- 预取：下钻到某市后，空闲时预取相邻的市（按锚点距离取最近 8 个）
- 取失败：该市保持市级样态，右上角给一次可重试的轻提示，不弹窗

## 10. 性能

- **区县层不要用 `feDropShadow`。** 现在点亮的市靠 `filter="url(#soft)"` 托底投影，区县数量上来之后滤镜数量是渲染开销的第一嫌疑。区县层改用描边表达层次。
- 区县 path 按「可见市集合 + 选中态」做 key 缓存，集合没变就不重建 DOM（原型里验证过，这一条是区县层能流畅拖动的关键）
- 目标：区县层拖拽稳定 60fps；首次下钻到可交互 < 400ms，分片已缓存时 < 50ms

## 11. 测试

项目现在**没有测试框架**，本次引入 `vitest`（devDependency）+ `npm test`。

- `src/lib/mapview.ts`：`progress` 的边界、`fitBox` 的宽高比与钳制、`drillBox` 对大市的 band 钳制、`visibleUnits` 的筛选
- `src/lib/visit.ts`：`foldToLevel`、市点亮聚合、区县三态判定
- `src/lib/validation.ts`：`level`/`parentAdcode` 的组合校验
- `build-map.py`：几何对齐回归（区县面积之和 vs 市面积，误差 < 1%）与新旧 `cn.json` 的坐标差回归，作为脚本的自检输出，不进 vitest

组件层不做快照测试 —— 这套东西的正确性主要在视窗数学和聚合语义上，那两块是纯函数。

## 12. 分期

| 期 | 内容 | 产出可验证的东西 |
|---|---|---|
| P1 | 重生成 `cn.json` + 固化 `tf` + 区县分片 + `index.json` + `names.json` | 体积实测数字、几何对齐回归通过 |
| P2 | schema（`level`/`parentAdcode`）+ API + 校验 | 能用 API 写入一条区县记录 |
| P3 | 层级抽象 + 组件拆分 + 区县渲染 + 面包屑 | 能缩放下钻、能点区县 |
| P4 | 抽屉 / 统计 / 搜索 / 回放适配 | 三种区县状态、斜纹补记、跨层搜索 |
| P5 | 性能与移动端（捏合下钻、抽屉宽度、标签密度） | 目标帧率与下钻耗时 |

P1 是闸门：体积或几何对齐不达标，后面全部要重新评估。

## 13. 风险

- **`cn.json` 重新生成的差异。** 投影参数是从注释里恢复的，可能与当初生成时有细微不同。§2.1 的坐标差回归就是为了在第一步把这件事钉死。
- **分片体积未实测。** 目前 40KB / 12MB 的目标是估的，P1 出数后可能要回头调 `eps`，甚至改成「按省分片」。
- **区划调整。** 撤县设区比地级市变动频繁，adcode 会变。`index.json` 里记 `fetchedOn` 和数据源版本，重抓时能对照出哪些市的下级变了。
- **band 阈值的手感。** 210/110 是在 1180px 宽的原型里调的，不同容器宽度下手感会变。P5 要在真机上复核，必要时把 band 改成按容器宽度归一化。
